# Working notes for Claude

A PopTracker pack for the Bug Fables Archipelago randomizer. `PLAN.md` is the plan and its decisions; the randomizer
is its own repo (a sibling checkout, `../bug_fables_ap`), and its rules carry over here where they apply.

## Starting a session

- Read `PLAN.md`, then in the randomizer: the pack's build steps in `agent_docs/apimplementation.md` (42, and 56 on;
  how the pack was built so far, each one's Status line), the latest entry of `agent_docs/log.md`, and its local
  `TO-CHECK.md` (what the user has seen in PopTracker, what's still to see).
- Work that needs the apworld changed happens in the randomizer's repo, under its own CLAUDE.md and hooks.

## What never changes

- **The logic is generated from the apworld, never written by hand** (`tools/export.py`): the pack can't drift from
  the seed it tracks. What the export can't express, the apworld fixes in the randomizer's repo, Archipelago's way;
  when the randomizer's preflight blocks Archipelago's standard way, ask the user to widen it, never code around it.
- **The map comes from the game's own data** (`data/`, regenerated by `tools/`): positions are facts read from the
  game, recorded in the randomizer's `MEASURED.md`. Its pictures are the game's, rendered by the mod's dev console
  (`worldmap`, `roomshot`); what the game has no picture of is drawn by code.
- **Each step is written up in the randomizer's `agent_docs/apimplementation.md`** as a build step (the user,
  2026-10-03): how the pack was built, and why (lupa included), committed there in the same session.
- **No AI art; game art only as the game shows it** (the user, 2026-10-13): the pause map and the rooms, rendered
  from the game; the user picks every look on screen.
- **Licence first:** a project with no row in the randomizer's `agent_docs/licensing.md` is off limits, its licence
  included, until the user says yes; then its licence, then its row, committed, before anything else of it is read.
  Never copy another project's code. **Never look at another Bug Fables project.**
- **Facts come from docs and source, never memory:** PopTracker's `doc/` (re-read before each new use; it changes),
  Archipelago's docs at the tag the randomizer targets, the apworld itself.
- **No personal username, home path or machine detail in any tracked file.**

## Who verifies what

- **The user verifies the pack in PopTracker; you verify the code.** `tools/test.ps1` runs the tests (the export,
  lupa parity against the apworld's own logic) and PopTracker's `pack-checker`: all pass before a commit.
- **Nothing on screen is "verified" until the user confirms it.** Ask before starting PopTracker or a server, then
  close what you started. Ask before touching PopTracker's install, the game, or the Archipelago checkout.

## How to

- **Set up once:** `python -m venv --system-site-packages .venv`, then `.venv\Scripts\python -m pip install -r
  requirements-dev.txt` (the system Python has Archipelago's requirements).
- **Test:** `tools\test.ps1 -Archipelago <your Archipelago checkout>` (the randomizer's world linked in as
  `worlds/bug_fables`): the export, parity on 200 seeds, `pack-checker` strict. The export alone:
  `python tools/export.py --archipelago <checkout>`; its output is committed.
- **Game data:** `tools/rooms.py` and `tools/map_areas.py` read the mod's `bugfablesap-entitydump.tsv` and
  `bugfablesap-mapdump.tsv` from your Bug Fables install's `BepInEx` folder (written by the mod's `EntityDump` and
  `MapDump` debug settings); `tools/rooms.py` also reads map names from the randomizer's gitignored `decompiled/`.
- **The game's pictures** (the game running the mod's dev build, `DevConsole` and `DevCommandFile` on; ask first):
  1. a seed's scenery lists: in the randomizer, `python dev-scripts/live-slot-data.py --archipelago <checkout> --yaml
     <a player file with every option at its default> --out <file>`;
  2. the dev console's `roomstates <file>`, then `worldmap` and `roomshot all` (written to the `BepInEx` folder; every
     rule for a room's picture lives in the mod's `Dev/MapShots.cs`, its reasons in the randomizer's
     `documentation.md` §7);
  3. `tools/world_map.py <BepInEx folder>` and `tools/room_pictures.py <BepInEx folder>`, then the export.
- **Release** (with the randomizer's release of the same world version): `package_version` bumped, the export run
  against that release's tag, the tests, `python tools/release.py check vX.Y.Z --randomizer ../bug_fables_ap`, pushed;
  then a release tagged `vX.Y.Z` published on GitHub, highlights as bullets. `.github/workflows/release.yml` checks
  its zip and adds it to `versions.json` on the `versions` branch, where PopTracker looks for updates.
- **See it** (ask first): PopTracker's `poptracker.exe --pack-variant map "<this folder>"` loads the pack from here,
  nothing copied. Its reload button doesn't pick up a changed map image: close it and start it again.

## Working with the user

- Commit freely, straight to `main`; never create a branch. Push only when told, in that message. Subjects:
  imperative, 72 characters at most.
- Never suggest stopping or resuming later. Small runnable steps, each with a visible outcome.
- Comments are lean: one line, only where the code can't say it.
